# ARKAON 배포 전 점검·보완 보고체계

## main 미병합 상태의 시험후보

실기기 시험과 통합 흐름 분석에 필요한 것은 `main` 병합 자체가 아니라 시험할 소스 계보가 하나의 불변 후보로 고정됐는지 여부다. 최신 기능계보 HEAD, 초기 `main`, 포함 PR, 소스트리 digest를 Integration Candidate로 기록한다. 시험빌드·계약시험·실기기 결과는 모두 같은 후보 커밋을 참조해야 한다.

따라서 운영승인 전에는 `main`을 보호하면서 검토용 통합 후보를 시험할 수 있다. 반대로 여러 PR의 임의 조합이나 커밋이 다른 증거는 하나의 출시 근거로 인정하지 않는다.

## ARKAON 보고 범위

ARKAON은 소스계보, 회귀시험, 정적보안, Migration 복구, 전자계약, 실기기 계획, 서명된 시험빌드, 비운영 자격증명, Rollback 훈련, 개인정보·법률검토와 운영자 승인을 점검한다.

각 미비사항에는 심각도, 담당 역할, 증거 digest와 구체적인 보완조치를 붙인다. 실패·누락·만료 또는 다른 커밋의 증거는 `BLOCKED`로 보고한다. 실기기 시험 준비상태와 운영 배포 준비상태는 분리해 보여준다.

## 권한 경계

ARKAON은 보완 코드를 작성하고 재시험할 수 있지만 자신의 보완안을 스스로 승인할 수 없다. 실패 시험 완화, 점검 생략, `main` 병합, 실제 배포, 운영 자격증명 사용도 금지한다. 모든 점검이 통과해도 최대 판정은 `READY_FOR_OPERATOR_REVIEW`이며 병합·배포 권한은 최인석 운영자에게 남는다.

현재 보고서는 합성 증거만 생성한다. 실제 실기기 시험 전에는 서명된 비운영 빌드, 폐쇄 Sandbox, 시험용 계정·기기, 데이터 초기화와 Rollback 절차가 별도로 준비돼야 한다.
