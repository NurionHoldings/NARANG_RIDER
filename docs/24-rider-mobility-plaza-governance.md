# 라이더 모빌리티 광장 기반계층과 ARKAON 감독

## 목적과 현재 판정

금융·보험·바이크·용품·정비·렌탈 입점 광장의 공통 통제를 먼저 구축한다. 현재 구현은 합성 공급자와 합성 상품만 처리하며 출시 상태는 `BLOCKED`다. 실제 업체 입점, 금융·보험 신청, 계약, 결제, 송금, 실제 개인정보 처리는 포함하지 않는다.

## 구성 단계부터의 ARKAON 개입

ARKAON은 요구사항과 공식 근거의 연결, 위협모델, 공급자 증거 누락, 계약시험, 약관 digest 변경, 비교기준 회귀, 후원·수수료 이해충돌, 증거 만료를 관찰한다. 관찰 결과는 `HUMAN_REVIEW`, `REQUEST_EVIDENCE`, `PROPOSE_SUSPENSION` 중 하나의 제안으로만 제출된다. ARKAON은 금융 승인·금리 결정·보험 인수·적합성 결론·계약 체결·자금 이동·자동 제재·외부업체 연락·운영 활성화를 수행할 수 없다.

## 입점과 상품 상태기계

입점은 `Draft → Evidence Review → Contract Test → 에테르니언 심사 → 운영자 결정 → Sandbox Enabled` 순서를 강제한다. 규제영역인 할부금융과 보험은 자격 증거 참조가 없으면 등록할 수 없다. 에테르니언 심사와 운영자 결정은 동일 참조를 사용할 수 없다.

상품은 `Draft → Human Review → Sandbox Visible → Withdrawn`으로 관리한다. 모든 계약 체결은 인허가를 갖춘 외부 업체 시스템에서만 가능하도록 표시하며, 현재 단계에서는 실제 신청 링크도 활성화하지 않는다.

## 비교와 이해충돌

비교 점수는 공개된 요소와 가중치로만 계산한다. 소개수수료와 후원 여부는 결과에 공개하지만 점수에는 반영하지 않는다. 금융상품의 경우 월 납입액 하나만으로 순위를 만들지 않고 총비용·기간·중도상환·연체 조건을 별도 요소로 확장해야 한다. 보험은 보험료와 보장·면책·자기부담금을 분리해야 한다. 이 구체 스키마는 공식 공급자 계약과 전문 법률검토 이후 후속 기능에서 확정한다.

## 데이터 경계

나랑라이더와 다른 플랫폼 사이에는 정책·스키마·평가방법·합성시험만 재사용한다. 회원 식별자, 주문, 위치, 정산, 신용, 보험 자료는 혼합하지 않는다. 금융·보험 가입 여부를 배차, 보수, 계정상태 또는 제재에 사용하지 않는다.

## 운영감시와 유지보수

각 감시 Snapshot은 정책, 공식 근거, 계약시험, 관찰 결과의 SHA-256을 묶는다. 공식 근거가 만료되거나 약관 digest가 바뀌거나 중대한 관찰이 발생하면 실패 폐쇄한다. 단, 실패 폐쇄는 자동 계약해지나 업체 제재가 아니라 신규 합성 평가 중단과 사람 검토 요청을 뜻한다.

공식 근거 Registry는 조사 대상을 기록한 것이며 법률 자문이나 서비스 적법성 승인이 아니다. 실제 출시 전 금융·보험·전자상거래·개인정보 분야별 독립 전문검토와 입점업체 자격 확인이 필요하다.
