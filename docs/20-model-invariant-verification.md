# 결정론적 모델·불변식 검증 (#046)

기준일: 2026-09-16

## 목적과 범위

이 검증층은 운영 기능이 아니다. 고정 seed로 생성한 명령열을 간단한 참조 모델과 실제 도메인 객체에 동시에 적용해 상태·버전·이벤트·원장 결과를 비교한다. 외부 네트워크, 실데이터, 운영 자격증명 및 시간 의존성을 사용하지 않는다.

## 검증 매트릭스

| 불변식 | 모델/기존 계약 증거 |
|---|---|
| 합법적 주문 상태 전이 | 참조 전이표와 `OrderRepository` 상태·버전·이벤트 비교 |
| 주문당 활성 호출 최대 1개 | 호출 순서 permutation과 `RiderCallService` 중복 차단 |
| 거절·취소 무불이익 | 취소 보수 보존 및 `rider_penalty_allowed=false` |
| 원장 균형·보수 비감소 | 모든 거래 debit=credit, 참조 보수 음수 금지 |
| 정확 재전송 멱등·변경 재전송 차단 | 주문·호출·콜백 재실행과 #045 충돌 회귀 계약 |
| 지사 격리·개인정보 최소화 | 기존 PostgreSQL RLS/API/관측성 계약을 전체 pytest에서 동시 실행 |
| 콜백 순서·send/ack 복구 | 단조 sequence, ack 후 재시작 재생 |
| 금융 2인 승인 | 기존 정산 지급지시 요청자·승인자·실행자 분리 계약 |
| AI 금지 권한 | `ForbiddenAuthority` 핵심 집합 고정 및 기존 ARKAON 전체 계약 |
| 증거 nonce 1회 사용 | 기존 배송증거 grant 재사용 차단 계약 |
| 감사기록 append-only | 재시작 전후 감사 순서·중복 없음 비교 |
| 분쟁·개인정보·사고 흐름 | 기존 casework/privacy/incident 상태계약을 동일 CI 회귀군에 포함 |

## 장애와 동시성

- commit 전 장애는 상태를 바꾸지 않는다.
- commit 후, send/ack 후 장애는 승인된 명령만 재생해 같은 상태를 복원한다.
- 두 호출 명령의 제한된 순열을 모두 실행해 순서와 무관하게 활성 호출 상한을 확인한다.
- 실패 시 seed, 실패 step, 그 시점까지의 명령열을 단일 JSON으로 예외에 남긴다.

CI는 seed 8개×80단계를 항상 실행하고 JSON 증거를 14일 보존한다. 수동 `Large model invariant verification`은 seed 256개×1,000단계를 실행한다. 난수는 `random.Random(seed)`에만 의존하므로 같은 커밋·seed는 같은 명령열을 생성한다.

## Mutation probe

참조 모델의 주문 버전을 의도적으로 변경한 뒤 비교기가 반드시 실패하는지 확인한다. 이는 모델 비교 자체가 형식적인 통과 장치가 아님을 증명한다. 운영 코드는 변경하지 않는다.
