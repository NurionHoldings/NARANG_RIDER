# 관리자–ARKAON 대화·부분수정 통제

## 관리자 컨트롤 창

나랑라이더 권한자는 관리자 화면에서 ARKAON과 요구사항, 수정 범위, 위험, 시험방법을 대화할 수 있다. 대화 메시지는 이전 메시지 digest와 연결하며 비밀번호·토큰·주민등록번호 형태의 입력을 거부한다.

부분 수정지시는 기준 후보 HEAD, 허용 파일경로, 수정 목적과 요구사항을 명시한다. ARKAON이 만드는 수정안은 지정 경로 안의 변경요약, patch digest, 시험계획과 위험기록으로 제한된다. 다른 경로나 오래된 HEAD에 대한 수정안은 실패 폐쇄한다.

## 수정 상태기계

`PROPOSED → PREVIEWED → OPERATOR_APPROVED → REVIEW_BRANCH_APPLIED`

운영자는 diff·시험·위험·사전보완가이드를 확인한 다음 검토 브랜치 반영만 승인할 수 있다. 승인 시에도 `main` 병합, 실제 배포, 운영환경 변경은 일어나지 않는다. ARKAON은 자신이 만든 수정안을 승인할 수 없다.

## 사전보완가이드 갱신

수정안 생성, 미리보기, 운영자 승인, 검토 브랜치 반영은 모두 수정 이벤트다. 각 이벤트 직후 변경 경로를 다시 분석해 새로운 `guidance_version`과 SHA-256 digest를 생성한다. 이전 가이드는 덮어쓰지 않고 이력으로 보존한다.

가이드 갱신이 생성되지 않은 수정상태는 완료로 취급하지 않는다. 소스·정책·Workflow·Migration·Frontend·전자계약별 시험 및 검토사항은 기존 ARKAON 기여자 가이드 규칙을 재사용한다.

## 운영 경계

현재 구현은 합성 검토브랜치 계약과 UI 초안이다. 실제 GitHub 파일쓰기, 운영 자격증명 사용, 자동 병합·배포는 연결하지 않았다. 향후 실제 관리 API를 연결할 때도 HttpOnly 세션, CSRF, RBAC, 최신 버전 검사, 감사로그와 운영자 명시승인이 선행돼야 한다.
