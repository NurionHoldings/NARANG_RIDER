# MVP foundation contract

## 구현 범위

첫 수직 슬라이스는 다음 네 경계만 구현한다.

1. 정수 원화 값 객체와 공개 단가 정책
2. 거리·대기·복귀거리·묶음·안전 가산을 항목별로 보이는 견적
3. longest-available FIFO와 결정 입력을 남기는 배차 영수증
4. 고객·점주 재원과 라이더·플랫폼·안전·지역기금 사용을 맞추는 정산 분개
5. 사후 조작 민원을 사람심사로 보내는 개인정보 최소형 Delivery Evidence Bundle

주문 UI, 실시간 GPS, 결제·송금, 보험 청구, 고객 개인정보, 실제 AI 모델은 포함하지 않는다.
따라서 저장소에는 비밀값·개인정보·실제 고객 주문이 없다.

## 불변식

- 금액은 부동소수점이 아닌 정수 원화만 사용한다.
- 공개 견적의 `고객 부담 + 점주 부담 = 라이더 지급 + 플랫폼 실비 + 안전기금 + 지역기금`이다.
- 점주 배달분담 상한을 넘는 견적은 생성하지 않는다.
- 라이더에게 수락 전 비용차감 건당·시간당 예상 순수익을 제공한다.
- 단가 정책 ID와 유효시각을 견적에 고정한다.
- 배차는 적격·안전 후보만 대상으로 하고 대기 시작시각, 픽업거리, 안정적인 rider ID만
  tie-break에 쓴다.
- 거절횟수·수락률·사고/보험이력·보호특성·AI 노동자 점수는 배차 입력으로 요청되는 즉시
  fail-closed한다. 알 수 없는 feature도 허용하지 않는다.
- 정산 transaction은 debit과 credit이 같아야 하며 ID 재사용을 거부한다. 수정은 향후
  보정 transaction으로만 표현한다.

## Delivery Evidence Bundle

- 갤러리 업로드를 금지하고 서버가 주문·배차·라이더에 묶어 발급한 짧은 TTL one-time
  nonce를 인앱 카메라 화면에 표시한다.
- 촬영 범위는 `문 앞 지정 인계 위치의 배달음식 포장 외관·봉인·누수 여부`뿐이다. 고정
  가이드 안에서 2~3프레임 burst를 찍고, 서버는 최적 한 장의 SHA-256과 프레임 일관성
  digest만 증거 영수증에 남긴다.
- 사람·신체, 실내/현관 내부, 생활물품, 우편물/송장, 차량번호, 공동현관 출입정보,
  타 주문정보는 거부한다. 불가피한 호수·문패는 저장 전에 마스킹하고 마스킹 전 원본은
  보존하지 않는다. EXIF 제거·MIME/크기·악성파일 검사를 통과해야 한다.
- 수령인에게 증거 생성과 수령시각, 이의제기 경로를 알린다. 공개 요약에는 라이더 정보,
  정밀주소, 원본 metadata를 넣지 않는다. 서버 검증 직후 개인정보 마스킹 사진, 배송시각,
  봉인상태와 정확히 `개봉 전 외관 이상이 있으면 먼저 신고해 주세요` 문구 및
  `외관 이상 신고` 버튼을 멱등 전송한다. 버튼은 인앱 실시간 촬영으로 연결하며 접근성
  label을 제공한다. 안내 확인은 권리 포기나 자동기각 근거가 아니다.
- 국물·음료 등 고위험 주문은 점주가 포장완료시각·봉인번호와 함께
  `double_packaging=true/false/not_applicable`를 append-only로 선언한다. 고위험 주문에는
  not_applicable을 허용하지 않는다. 픽업 화면과 고객 주문상세에 같은 값을 표시하며 false를
  라이더 책임으로 추론하지 않는다.
- 카메라 고장·안전위험이면 일회용 배송코드, 봉인번호, 고객 수령확인을 허용하고 촬영
  누락을 페널티로 쓰지 않는다.
- 고객 파손 민원도 갤러리가 아닌 실시간 인앱 burst로 받는다. 배송 영수증에서 외관·
  봉인이 정상이었는데 새 훼손이 보이면 `POST_DELIVERY_TAMPER_REVIEW`로 보내지만 자동환불,
  자동기각, 자동제재는 모두 금지한다. 내부 누수와 정당 민원도 사람의 환불심사를 받는다.
- 반복·연계·디바이스·사진재사용 신호는 조사 순서에만 쓰고 책임 판정 입력으로 쓰지 않는다.
  분쟁 중 라이더 보수는 지급하며 귀책 확정 전 환수하지 않는다.
- 원본은 최소 권한으로 단기 보관 후 자동삭제한다. 분쟁 legal hold와 모든 원본 접근은
  감사로그에 남긴다. 증거를 AI 학습·마케팅·다른 분석에 재사용하지 않는다.

## 다음 단계 의존성

`Order state machine → Quote persistence → Offer lease → Delivery proof → Settlement adapter`
순서로 확장한다. 실제 결제 전에는 webhook 순서역전·중복·위조와 계좌변경 2인 확인을
추가해야 한다. AI 기반 ETA는 공개 규칙 fallback과 drift 관측이 갖춰진 뒤에만 연결한다.
